# EVT-006 — repeated microphone boom cycles

Date: 2026-09-16
Transport: hidraw, opened read-only
Action: three cycles, boom raised then lowered

## Observed normalized sequence

```text
raise:  2f 02, 06 00, 2f 00
lower:  2f 02, 06 01, 2f 00
raise:  2f 02, 06 00, 2f 00
lower:  2f 02, 06 01, 2f 00
raise:  2f 02, 06 00, 2f 00
lower:  2f 02, 06 01, 2f 00
```

## Confirmed mapping

| Report | Payload | Meaning |
|---|---:|---|
| `0x06` | `0x00` | Microphone muted; boom raised |
| `0x06` | `0x01` | Microphone active; boom lowered |
| `0x2f` | `0x02` | HID Telephony Phone Mute usage asserted |
| `0x2f` | `0x00` | HID Telephony Phone Mute usage released |

Report `0x06` is the persistent vendor-defined microphone state. Report
`0x2f` is a momentary standardized host-control pulse surrounding every state
change. Six consecutive transitions followed the same pattern.

## Independent physical indicator

The headset microphone has an LED that is illuminated while muted and dark
while active. This independently agrees with the Report `0x06` mapping above.

The descriptor also defines Output Report `0x2f` on the LED usage page and
includes Usage `0x09`, which the USB HID Usage Tables name **Mute**. This makes
host-driven mute indication structurally possible, but does not prove that the
microphone LED is controlled through that report: it may be controlled locally
by the headset. No Output Report has been sent to test this.
