# EVT-023 — lighting synchronization enabled and disabled

Date: 2026-09-16
Transport observed: Windows 11 VM, USBPcap, dongle `0ecb:2069`
Initial condition: lighting enabled; synchronization disabled
Action: enable synchronization, wait, then disable synchronization

## Observed

Enabling synchronization caused QuantumENGINE to send a group of Feature
Reports beginning at capture time 3.956 s. The group included:

- Report `0x4c` for zones `0x00` and `0x01`, both with parameters `64 05`;
- Report `0x4d` entries for both zones;
- Report `0x4b` payload `01`, refreshing the global lighting-enabled state;
- Input Report `07 01`, confirming lighting remained enabled.

Disabling synchronization caused another, smaller set of `0x4c` and `0x4d`
writes beginning at 13.801 s, followed by the same `4b 01` / `07 01`
lighting-enabled refresh. No unique boolean field or distinct report appeared for
the synchronization switch.

## Interpretation

Light synchronization is likely implemented in QuantumENGINE by copying or
reapplying per-zone animation data. It does not appear to be an independently
stored device state. This remains a strong hypothesis because unchanged values
may be omitted by the application, and the two zones initially had matching
patterns.

The capture further supports:

- Report `0x4c`: zone-level animation header;
- Report `0x4d`: individual animation segment definition;
- first byte after `0x4c`/`0x4d`: zone index (`00` or `01`).
