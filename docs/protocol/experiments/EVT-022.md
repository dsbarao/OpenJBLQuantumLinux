# EVT-022 — lighting disabled and enabled

Date: 2026-09-16
Transport observed: Windows 11 VM, USBPcap, dongle `0ecb:2069`
Initial condition: QuantumENGINE connected and stable
Action: disable lighting, wait, then enable lighting

## Observed sequence

| Capture time | Transfer | Bytes | Meaning |
|---|---|---|---|
| 11.737 s | SET_FEATURE Report `0x4b` | `4b 00` | request lighting disabled |
| 11.785 s | Interrupt IN Report `0x07` | `07 00` | lighting disabled confirmation |
| 17.670 s | SET_FEATURE Report `0x4b` | `4b 01` | request lighting enabled |
| 17.728 s | Interrupt IN Report `0x07` | `07 01` | lighting enabled confirmation |
| 17.768 s | Interrupt IN Report `0x08` | `08 55` | battery 85% |

The state confirmations followed their requests in roughly 48–57 ms.

## Conclusion

- Feature Report `0x4b` controls the lighting enable state.
- Input Report `0x07` publishes the resulting lighting enable state.
- Input Report `0x08` carries battery percentage. Its value changed from the
  earlier `0x5a` (90) to `0x55` (85), providing the independent second charge
  level needed to confirm the interpretation.

Only the Input Report mappings are enabled in the Linux monitor. No USB write
support was added.
